# 06 · План команды

Разработка на площадке займёт часы, поэтому выигрывает подготовка. К старту команда должна знать модель данных, контракт API и ожидаемые числа сценариев наизусть.

## Роли

| Роль | Отвечает за | Кто |
| --- | --- | --- |
| Капитан-аналитик | Экономическая модель, таблица допущений, презентация, ответы жюри | |
| Backend 1 | Остатки, заказы, резервы, статусы, проводки | |
| Backend 2 | Маршрутизация, инциденты, длительное хранение, сценарные тесты | |
| Frontend | UI ПВЗ, кабинет продавца, экраны аналитики, панель сценариев | |
| Инфраструктура | Docker Compose, сид-данные, README, отчёт проверки, резервное видео, сдача | |

## До хакатона

- [ ] **Неделя 1.** Уточнить у оргкомитета даты, длительность первого дня и правила по заготовкам. Распределить роли. Капитан пересобирает модель со своими допущениями и умеет объяснить каждую формулу.
- [x] **Неделя 2.** Универсальное окружение без предметной логики: Docker Compose, каркас FastAPI с ролями, миграции, оболочка React, CI. *(этот репозиторий)*
  - [ ] Указать ссылку на репозиторий в заявке.
  - [ ] Каждый делает учебную сквозную фичу на отдельной ветке, чтобы освоить стек (в `main` не сливать).
- [ ] **Неделя 3.** Проектные материалы на бумаге: схема БД, список эндпоинтов, таблицы ожидаемых значений по сценариям, шаблон презентации. Две репетиции 8-минутной защиты с таймером.

## День хакатона (~7 часов до 16:00)

| Время | Что делаем |
| --- | --- |
| 0:00–0:30 | Сверить разъяснения оргкомитета, зафиксировать план |
| 0:30–3:30 | Ядро: схема БД, остатки, заказы, проводки, маршрутизация; UI ПВЗ; сид-данные. **К 3:30 сценарий 1 проходит сквозно** |
| 3:30–5:30 | Сценарии 2–5, экраны аналитики, тесты; капитан пишет презентацию |

| 6:30–7:00 | Итоговый коммит, хеш, архив, PDF, сдача комплекта с запасом |

## Как использовать LLM

Сначала контракт, потом код: дать модели схему БД, список эндпоинтов и таблицу ожидаемых чисел и просить по одному модулю с тестами. Тесты сценариев писать по таблицам из [04-scenarios.md](04-scenarios.md) — они ловят ошибки сгенерированного кода. Каждый фрагмент читает и принимает человек. Использование записывать в [DISCLOSURE.md](../DISCLOSURE.md).

## Риски самой команды

- **Числа в UI, отчёте и слайдах расходятся.** Лечится одним движком расчётов и отчётом, который генерируют тесты.
- **Участник не может объяснить свой код или формулу** (п. 8.3, 9.6). Лечится репетициями с вопросами друг другу.
