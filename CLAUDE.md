# Mesh-доставка с хранением в ПВЗ — хакатон RWB

Контекст задачи, модель и ожидаемые числа — в `docs/`. Перед изменениями в предметной логике сверяйся с `docs/03-architecture.md` и `docs/04-scenarios.md`.

## Правила хакатона, влияющие на работу

- Предметный код пишут сами студенты (п. 8.1 положения). Каждый участник должен объяснить код (п. 8.3). Не генерируй крупные куски логики без запроса; объясняй, что пишешь.
- Любое использование ИИ записывается в `DISCLOSURE.md`.
- Все тарифы — синтетические допущения, не выдавать за тарифы RWB.
- Заглушки внешних систем (хаб, магистраль, оплата, приложение покупателя) — только под `/stub/*` и с плашкой «ИМИТАЦИЯ» в UI.

## Инварианты

1. Деньги — в копейках, `int`/`bigint`, никакого float.
2. Все начисления — только через одну функцию проводки; сумма каждой проводки = 0.
3. Одна единица — не больше одного активного резерва.
4. Статусы — только по разрешённым переходам, с проверкой версии.
5. Изменяющие запросы принимают ключ идемпотентности.

## Команды

- `docker compose up --build` — всё окружение
- `make test`, `make lint`, `make migration m="..."`
